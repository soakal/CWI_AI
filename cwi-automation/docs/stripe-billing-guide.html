Stripe Billing Setup Guide

Step-by-step instructions for setting up recurring monthly subscriptions, webhooks, and client billing inside the CWI AI system.

ⓘ

Overview

How Stripe fits into the CWI AI billing stack
⌄

Stripe is the payment processor used for all CWI AI client billing. Every active client is billed monthly via a Stripe subscription.

  • Recurring billing — Stripe charges clients monthly on their billing anchor date. No manual invoicing required after setup.
  • Dunning management — Stripe automatically retries failed charges on a configurable schedule (default: 4 retries over 8 days) before marking a subscription as past-due.
  • Failed payment alerts — Scenario I (Make.com) listens to Stripe webhook events for invoice.payment_failed and sends the client an automated email with a portal link to update their card.
  • Scenario F (Make.com) logs successful payments and triggers onboarding or fulfillment steps as configured.
ⓘ
Always test with Stripe test mode cards before going live with a real client. Test card: 4242 4242 4242 4242, any future date, any CVC.

Create Products & Prices

Starter / Growth / Pro plans in the Stripe Dashboard
⌄
Starter
$197/mo
+ $499 setup fee
Growth
$397/mo
+ $499 setup fee
Pro
$597/mo
+ $749 setup fee

Steps — Create Each Recurring Product

  1. In the Stripe Dashboard, go to Product catalog (left sidebar) then click + Add product.

  2. Enter the Product name (e.g. "CWI AI Starter Plan").

  3. Under Pricing, set the model to Recurring.

  4. Enter the price (e.g. 197.00) and set the currency to USD.

  5. Set the billing period to Monthly.

  6. Click Save product. Repeat for Growth ($397/mo) and Pro ($597/mo).

Steps — Create Setup Fee Products (One-Time)

  1. Create another product: name it "CWI AI Setup Fee — Starter/Growth", pricing model One-time, price $499.

  2. Create a second one-time product: "CWI AI Setup Fee — Pro", price $749.

⚠
Do not mix recurring and one-time prices on the same product. Keep them as separate products so subscriptions stay clean.
2

Get Price IDs

Copy price_xxx IDs for use in .env files
⌄

After creating each product, Stripe generates a unique Price ID in the format price_xxxxxxxxxxxxxxxxxxxxxxxx. These are referenced by client automations.

How to Copy a Price ID

  1. Go to Product catalog → click on the product name.

  2. Scroll to the Pricing section on the product detail page.

  3. Find the price row and click the copy icon next to the Price ID (e.g. price_1Abc...).

  4. Paste it into the relevant client .env file.

Client .env Variables

# Recurring subscription price IDs STRIPE_MONTHLY_PRICE_ID_STARTER=price_xxxxxxxxxxxxxxxxxxxx STRIPE_MONTHLY_PRICE_ID_GROWTH=price_xxxxxxxxxxxxxxxxxxxx STRIPE_MONTHLY_PRICE_ID_PRO=price_xxxxxxxxxxxxxxxxxxxx # For a specific client, set the plan they're on: STRIPE_MONTHLY_PRICE_ID=price_xxxxxxxxxxxxxxxxxxxx
ⓘ
Stripe has separate price IDs for test mode and live mode. Make sure to use the correct set when deploying a client to production.
3

Create the Customer Portal

Self-service card update & subscription management
⌄

The Stripe Customer Portal lets clients update their payment method on their own — no need to contact you. The portal URL is embedded in failed-payment emails sent by Scenario I.

Enable the Customer Portal

  1. In the Stripe Dashboard go to Settings (gear icon) → Billing → Customer portal.

  2. Toggle the portal to Active / Enabled.

  3. Under Functionality, enable at minimum: Update payment methods and View billing history.

  4. Optionally configure your business branding (logo, colors) so the portal matches CWI AI style.

  5. Click Save changes.

  6. Copy the portal link shown at the top of the page (format: https://billing.stripe.com/p/login/...).

.env Variable

STRIPE_CUSTOMER_PORTAL_URL=https://billing.stripe.com/p/login/xxxxxxxxxxxx
✓
Scenario I uses this URL in the body of failed-payment alert emails so clients can self-serve without calling you.
4

Charge the Setup Fee

Collect one-time onboarding fee before work begins
⌄

Setup fees are collected before subscription creation. Use a Stripe Payment Link for the easiest client experience — they click, pay, done.

Option A — Payment Links (Recommended)

  1. Go to Payment Links in the Stripe sidebar → click + New.

  2. Click + Add a product → select your setup fee product (e.g. "CWI AI Setup Fee — Starter/Growth").

  3. Set quantity to 1. Optionally add a custom success message.

  4. Click Create link. Copy the URL and send it to the client via email or SMS.

  5. Do not start work until the payment shows as Succeeded in the Stripe Dashboard.

Option B — One-Time Invoice

  1. Go to Customers → find or create the client → click + Create invoice.

  2. Add the setup fee product as a line item.

  3. Set Due date to immediately or a short window (e.g. 3 days).

  4. Click Send invoice. Stripe emails the client directly.

⚠
Always collect the setup fee before creating the subscription or starting any build work. The subscription creation in Step 5 comes after payment is confirmed.
5

Create Subscription for New Client

Customer record, payment method, and recurring plan
⌄

A — Create the Customer

  1. Go to Customers in the sidebar → click + Add customer.

  2. Enter the client's name and email address. Add their business name in the description field.

  3. Click Add customer.

B — Attach a Payment Method

  1. On the customer record, scroll to Payment methods → click + Add.

  2. Enter the card details manually, or send the client a Setup link (Stripe generates a secure URL for them to enter their own card — preferred for remote clients).

C — Create the Subscription

  1. On the customer record, click + Create subscription.

  2. Click Add a product and select the correct plan (Starter $197, Growth $397, or Pro $597).

  3. Set the Billing cycle anchor to the 1st of the month for simplicity (all clients bill on the 1st).

  4. Review the proration charge if starting mid-month — adjust or waive as needed.

  5. Click Start subscription.

ⓘ
Using the 1st of the month as the billing anchor keeps all subscriptions on the same cycle, making monthly revenue tracking simple. Stripe will prorate the first charge for the current month.

After the subscription is created, copy the Customer ID (cus_xxx) and Subscription ID (sub_xxx) into the client's record in your CRM or onboarding doc.

STRIPE_CUSTOMER_ID=cus_xxxxxxxxxxxxxxxxxxxx STRIPE_SUBSCRIPTION_ID=sub_xxxxxxxxxxxxxxxxxxxx

Configure Webhooks

Connect Stripe events to Scenario F and Scenario I in Make.com
⌄

Webhooks let Stripe push real-time events to Make.com so your scenarios fire automatically when payments succeed or fail.

Add the Webhook Endpoint

  1. In the Stripe Dashboard go to Developers → Webhooks → click + Add endpoint.

  2. In the Endpoint URL field, paste the Scenario F webhook URL from Make.com (found in the scenario's Webhook trigger module).

  3. Under Select events, add the following events:

payment_intent.succeeded payment_intent.payment_failed invoice.payment_succeeded invoice.payment_failed customer.subscription.updated customer.subscription.deleted

  1. Click Add endpoint to save.

  2. On the endpoint detail page, click Reveal signing secret and copy it.

  3. Paste it into your .env file and into the Make.com webhook settings for signature verification.

.env Variable

STRIPE_WEBHOOK_SECRET=whsec_xxxxxxxxxxxxxxxxxxxxxxxxxxxx
⚠
The webhook signing secret is different from your Stripe API keys. Never share it publicly. Stripe uses it to verify that webhook payloads are genuinely from Stripe, not a spoofed request.

Scenario Routing

  • Scenario F — Triggered by payment_intent.succeeded / invoice.payment_succeeded. Logs the payment, updates the CRM, and fires fulfillment steps.
  • Scenario I — Triggered by invoice.payment_failed. Sends the client a payment failure alert email with their Customer Portal link (STRIPE_CUSTOMER_PORTAL_URL) so they can update their card.
✓
After adding the endpoint, use Stripe CLI or the Send test webhook button in the dashboard to fire a test event and confirm Make.com receives it before going live.
