How to Import a Scenario
Repeat these steps for each of the 15 scenarios in order
⌄
1
Open the Scenarios screen
Log in to make.com. In the left sidebar click Scenarios. Then click the blue Create a new scenario button (top right).
2
Open the Import Blueprint menu
On the blank scenario canvas, click the three-dot menu (⋯) in the top toolbar (next to the scenario name). Select Import Blueprint from the dropdown.
Screenshot note: The three-dot menu is in the top-centre toolbar area, not the left sidebar. It looks like three horizontal dots.
3
Select the JSON file
A file picker appears. Navigate to your make-scenarios/ folder and select the correct .json file for the current scenario (follow import order from Section 2). Click Open.
4
Save the blueprint
Make.com will load the scenario visually. Click Save (floppy disk icon, top right). The scenario is saved but not yet active — modules with missing connections will show orange warning triangles.
5
Assign connections to every module
Click each module that has an orange warning triangle. In the module settings panel, click the Connection dropdown and select the matching connection you created (see Section 4). If the connection doesn't exist yet, click Add to create it now.
Tip: Create all connections first (Section 4) before importing scenarios — it speeds up this step considerably.
6
Run a test
Click Run once (the play button). If the scenario is webhook-triggered, send a test payload using webhook-tester.html. Check the execution log at the bottom of the screen — each module should show a green bubble with the number of processed items. Red = error, click it to see the detail.
7
Toggle ON
When the test passes cleanly, flip the blue toggle switch in the top-right corner of the scenario editor to ON. The scenario is now live.
Reminder: Save again after toggling on to lock in the active state before moving to the next scenario.

Connections to Create
Create each connection once — reuse it across all scenarios
⌄
Best practice: Create all connections before importing scenarios. Go to Connections in the left sidebar and click Add connection for each row below.
Connection Name Service / Module Type What to Paste / Do
CWI Resend Resend (native module) Paste RESEND_API_KEY from .env — starts with re_
CWI HubSpot HubSpot — Private App Paste HUBSPOT_API_KEY — starts with pat-na1-
CWI Google Calendar Google Calendar — OAuth2 Click Sign in with Google and authenticate as brian@cwiai.net
CWI Google Sheets Google Sheets — OAuth2 Same Google account as Calendar — reuse the existing OAuth grant if prompted
CWI Stripe Stripe (native module) Paste STRIPE_API_KEY from .env — starts with sk_live_ (or sk_test_ for testing)
CWI Calendly Calendly — Personal Access Token Paste CALENDLY_API_KEY from .env
CWI Apollo Apollo.io — API Key Paste APOLLO_API_KEY from .env
CWI Freshchat Freshchat (HTTP module) Paste FRESHCHAT_API_KEY and set Base URL to your Freshchat domain
CWI OpenRouter HTTP — API Key header Header: Authorization: Bearer OPENROUTER_API_KEY — paste key from .env

Testing Checklist
Verify each scenario is firing and producing the correct output
⌄
🔨
Webhook Tester
Open webhook-tester.html to send sample payloads to each scenario's webhook URL. Select the scenario type from the dropdown to auto-fill the correct JSON body.
📋
Make.com History
In each scenario, click the History tab. Green bubbles = success. Red = error. Click any execution to see which module failed and the exact error message.
📧
Resend Dashboard
Check resend.com → Logs after running any scenario that sends email. Confirm the email was delivered to the correct address with the correct subject line.
👑
HubSpot CRM
After testing scenarios D, E, F, G, H, N: check HubSpot contacts and deals for the expected updates — stage changes, property writes, new notes.
